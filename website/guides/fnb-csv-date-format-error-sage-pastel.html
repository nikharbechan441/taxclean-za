The Root Cause of FNB CSV Import Crashes in Pastel Cashbook

First National Bank (FNB) allows users to download transactions as a Comma Separated Value (.csv) file directly from Online Banking Enterprise or Personal Online Banking. However, attempting to import this file directly into Sage Pastel Partner Cashbook results in immediate failure:

Error: "Invalid Date at line 4" or "Column count mismatch at line 1"

This happens because FNB's default CSV structure violates three core requirements of Sage Pastel Partner:

  1. 3 Top Metadata Lines: FNB prepends the file with account details (Account Name, Number, Balance). Pastel expects line 1 to be the first transaction.
  2. Date Format Mismatch: FNB outputs dates as YYYY/MM/DD. Sage Pastel expects DD/MM/YYYY.
  3. Unquoted Description Commas: FNB store names often include commas (e.g. ENGEN, QUICKSHOP 102). When unquoted, CSV parsers split this into two columns, shifting the amount into the balance column.

The Fix: Transforming FNB CSV to Pastel Specification

  1. Open the downloaded FNB CSV in Notepad or Excel.
  2. Delete Rows 1, 2, and 3 completely so that your first actual transaction is on Row 1.
  3. Select the Date column and format to dd/mm/yyyy.
  4. Ensure amounts are single-column (negative for payments, positive for receipts).
  5. Save the file as CSV (Comma Delimited) (*.csv).

FNB exports dates as YYYY/MM/DD, whereas Sage Pastel requires DD/MM/YYYY. Furthermore, the first 3 lines contain account text rather than dates.
